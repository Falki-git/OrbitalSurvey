# Patch Manager

PatchManager is the system Redux uses to change game content with Lua scripts. You write a small `.lua` file, drop it into a mod, and PatchManager runs it while the game loads its assets. Your script can edit existing content (make a part lighter, recolor a planet, move a tech node) or add brand new content (a new moon, a new resource, a new mission step), all without compiling any C#.

These docs are written for people writing patches. They assume you can read a little Lua but not that you know anything about the game's internals. Every page leads with a real, working example and then explains what it does.

## How to read this

If you are brand new, start at [Getting Started](/doc/getting-started-M6lopbmYlB) and go in order. It installs the editor tooling, walks you through your first patch, and explains where patch files live.

Once you can write a basic patch, [Core Concepts](/doc/core-concepts-JzW14TdnTL) is the heart of the docs. It covers how patches are sequenced, how to target the right assets, how to add and remove data, and how to keep your patches from fighting other mods.

After that the docs split by what you are patching:

* [Generic JSON API](/doc/generic-json-api-fqEwMuvrGb) patches any asset by its raw JSON, with no game-specific helpers. It is the foundation the typed modules are built on.
* [Typed Modules](/doc/typed-modules-nMMO0SZ6ac) add convenience helpers for specific content: parts, planets, resources, science, missions, variants, and audio.
* [Advanced Topics](/doc/advanced-topics-uybkyjgPpJ) covers sharing code between files, cross-mod compatibility, converters, caching, and extending PatchManager from C#.
* [Reference](/doc/reference-57SBVho6Kg) is the lookup material: a method cheat sheet, the enum value lists, and a glossary.

## The two globals you will use

Every patch script has two globals available the moment it runs:

* `PM` is the PatchManager library. You register patches through it (`PM.Parts:Patch(...)`, `PM.Planets:Patch(...)`, `PM.JSON:Patch(...)`, and so on).
* `J` is a small JSON helper for the few cases where plain Lua tables are not enough. See [Working with JSON](/doc/working-with-json-fWfY8KrejF).

You also get `ModId` and `Location` (who you are and where your files live), `Config` (your mod's settings), and `Log` (for printing diagnostics). Those are covered in [File layout and discovery](/doc/file-layout-and-discovery-vYcsLN5rtw), [Config integration](/doc/config-integration-aTM54Tfqkz), and [Reading the summary](/doc/reading-the-summary-8ahmOdWbza).

## A minimal example

This is a complete, real patch. Even without knowing the system, you can probably read the gist: it finds the part named `eva_kerbal` and raises how hard it can hit something before it breaks.

```lua
PM.Parts:Patch("KerbalImpactToleranceFix")
        :Named("eva_kerbal")
        :Do(function(part)
            part.crashTolerance = 30.0
        end)
```

The `:Patch` call names what you are doing, `:Named` narrows it to one part, and `:Do` is the change itself. Those three calls are most of what patching is. The one piece you cannot guess yet is where `eva_kerbal` comes from, and the next pages answer that.

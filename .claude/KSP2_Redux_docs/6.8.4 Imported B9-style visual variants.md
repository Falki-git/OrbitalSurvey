# Imported B9-style visual variants

This page documents the KSP1 import path that builds V-SwiFT data from B9 Part Switch-style source content.

## Local source

The relevant builder is `Redux.Ksp1Import.Ksp1B9PartSwitchVariantBuilder`.

## What it does

* scans KSP1 `MODULE` nodes for B9-style switch data
* creates a `Data_PartSwitch` object
* creates one `VariantSet` per imported switch group
* creates one `Variant` per imported subtype
* populates `ActiveVariants` with the default subtype selection
* emits serialized `PartComponentModule_PartSwitch` / `Module_PartSwitch` / `Data_PartSwitch` entries

## Imported behavior style

The importer primarily builds visual-state variants, including transform activation and texture-switch style behavior. That makes it a good reference for understanding how V-SwiFT is used as a compatibility layer rather than only as a hand-authored authoring surface.

## Why this matters

If you are porting KSP1 parts, this importer is the best grounded example of how Redux already maps an external variant system into V-SwiFT concepts.

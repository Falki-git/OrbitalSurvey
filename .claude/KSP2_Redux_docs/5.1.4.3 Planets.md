# Planets

`PM.Planets` patches celestial bodies and the things attached to them: the body's own properties, the galaxy that places it in orbit, and the atmosphere and cloud visuals layered on top.

## Patching a body

`PM.Planets:Patch(name)` patches a celestial body, targeted by body name (`Kerbin`, `Mun`, `Eve`, and so on). Inside the callback you get the body's properties and set fields directly. This real patch points Eve's reentry effects at a custom gradient:

```lua
PM.Planets:Patch("EveReentryGradient")
          :Named("Eve")
          :Do(function(body)
              body.atmosphericReentryVFXGradient =
                  "Assets/ReduxAssets/Definitions/CelestialBodies/KerbolSystem/Eve/EveReentry.png"
          end)
```

Vector and color fields are tables. This patch sets each body's dust color, sharing one helper across many bodies:

```lua
local function RGB(r, g, b)
    return function(body) body.MineDustColor = { x = r, y = g, z = b, w = 1.0 } end
end

PM.Planets:Patch("MunDustColor"):Named("Mun"):Do(RGB(1.0, 0.99, 0.87))
PM.Planets:Patch("EveDustColor"):Named("Eve"):Do(RGB(0.69, 0.57, 0.43))
```

## Adding a body to the galaxy

A new body is added to the galaxy definition, not created as a loose asset. `PM.Planets:PatchDefaultGalaxy(name)` patches the galaxy, and `galaxy:Add(guid, callback)` adds a body. This is how Redux adds the moon Drast:

```lua
PM.Planets:PatchDefaultGalaxy("AddDrast"):Do(function(galaxy)
    galaxy:Add("Drast", function(body)
        body.PrefabKey = "Celestial.Drast.Local"
        body.referenceBodyGuid = "Dres"
        body.OrbitProperties = {
            referenceBodyGuid = "Dres",
            inclination = 0,
            eccentricity = 0,
            semiMajorAxis = 434400,
            longitudeOfAscendingNode = 0,
            argumentOfPeriapsis = 0,
            meanAnomalyAtEpoch = 0,
            epoch = 0,
        }
    end)
end)
```

Adding a new fully working body is a large undertaking (it needs a prefab, orbit, properties, and usually science and atmosphere data). The galaxy `Add` call is only the placement step. Everything else should be done using the planet editing tools in the SDK, as there is a lot more than just the JSON data itself that goes into the body

## Atmosphere overrides

An atmosphere override tunes a body's atmosphere visuals and physics without editing the body itself. Every field except the body name is optional, so you set only what you want to change.

* `PM.Planets:PatchAtmosphereOverride(name)` patches an existing override.
* `PM.Planets:CreateAtmosphereOverride(bodyName, callback)` creates a new override for a body.

## Cloud overrides

Cloud overrides work the same way for volumetric clouds:

* `PM.Planets:PatchCloudOverride(name)` patches an existing override.
* `PM.Planets:CreateCloudOverride(bodyName, callback)` creates a new one.

A cloud override's `cumulusList` is a typed list keyed by layer name, so you reach a specific cloud layer by its `layerName` and edit it. The full set of atmosphere and cloud fields, which are extensive and rendering-specific, is in `pm-planets.d.lua`.

## Which surface to use

* Changing a body's physical or surface properties: `Patch`.
* Placing a new body: `PatchDefaultGalaxy` and `galaxy:Add`.
* Tuning how an atmosphere or clouds look: the override methods, so the body definition stays untouched and your visual changes are separable.

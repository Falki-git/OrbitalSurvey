# Variant

This page documents one concrete variant entry inside a `VariantSet`.

## Purpose

A `Variant` is one selectable option in a variant set. Its transformer list is where the authored behavior actually lives.

## Source-backed type

* C# type: `VSwift.Modules.Variants.Variant`

## Key fields

* `VariantId: string`
* `VariantLocalizationKey: string`
* `VariantTechs: list[string]`
* `Transformers: list[ITransformer]`

## Runtime role

* `VariantId` is the internal identifier and the stored active-selection value.
* `VariantLocalizationKey` supplies the display name. If it is empty, V-SwiFT falls back to `VariantId`.
* `VariantTechs` lists tech-node IDs required to unlock that choice.
* `Transformers` is the ordered list of actions and visualizers attached to the variant.

## Tech gating

If science mode is enabled, a variant with unmet `VariantTechs` requirements is treated as locked in OAB UI. Dropdown creation skips unavailable variants, while the popout UI shows the unmet requirements explicitly.

## Example

```patch
+Hydrogen {
    VariantLocalizationKey: "MyMod/Tank/Hydrogen";
    VariantTechs: [ advFuelSystems ];

    +ResourceContainerAdder {
        Containers: [ /* container definitions */ ];
    }

    +MassModifier {
        Modifier: 0.15;
    }
}
```

## Notes

The order of transformers inside a variant matters when V-SwiFT later stores saved-information entries, because those saved entries are indexed by transformer position.
